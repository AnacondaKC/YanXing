# YanXing v0.1.1

研行 0.1.1 是一次稳定性与部署优化更新，重点修复 AI 结构化分析和提示词预算问题，并精简 Docker 运行产物。

## 主要更新

### AI 分析稳定性

- 统一思维导图生成 Schema 与后端校验，最多支持五层节点。对名称合法、无额外字段的非根叶子节点，自动补齐遗漏的 `子节点: []`，减少不必要的模型重试；结构、类型、节点数量与层宽限制仍严格执行。
- 修复 TypeBox 校验错误适配，保留深层字段路径与期望类型，提供更易定位的中文纠错反馈。
- 自动补齐通过任务进度与 Worker 日志记录，不记录报告正文。

### 提示词预算与模型配置

- 设置保存、任务入队和模型执行共用提示词预算校验。不兼容的新任务在预留 Token 前拒绝，旧冻结任务在调用模型前终止，避免无效模型调用。
- 上下文不足时只截取报告正文，保留系统约束、任务要求、评价背景、纠错反馈及完整 Schema；预算不足的任务 API 返回 HTTP 409，并说明所需与可用字符数。
- 新建模型及首次初始化未显式指定输出上限时，默认最大输出 Token 调整为 **65,536**。已有模型、显式配置与冻结任务不变；运行时缺省回退仍为 16,384。

### Docker 与品牌配置

- 使用 Next standalone 与预编译 Worker、管理命令和 PDF/DOCX 解析子进程，仅打包实际追踪到的运行依赖、静态资源及许可文件，不再复制完整依赖目录或构建缓存。
- 程序和依赖保持 root 所有、运行用户只读，仅存储、运行缓存和临时目录可写，并补充隔离部署与权限冒烟测试。
- 品牌配置按请求读取，失败时回退默认品牌；管理 API 仍保持严格校验。

## 升级说明

1. 升级前备份数据库、上传文件和 `YANXING_SETTINGS_ENCRYPTION_KEY`，保留旧镜像以便回滚。本次 Docker 打包调整不改变数据库结构、数据卷或密钥。
2. 使用 `v0.1.1` 对应的仓库与 Compose 配置。Docker 中不再直接执行旧 `.ts` 路径或依赖 `tsx`，现有 Compose 管理命令用法保持不变。
3. 新建模型前确认服务支持所配置的输出上限；若收到预算不足的 409 响应，按提示调整上下文或提示词配置，已有模型配置不会自动升级。
4. 生产环境仍需 HTTPS；自动化测试不能替代真实模型兼容性与备份恢复验证。

## Docker 镜像

Release 发布后会自动运行 CI、Docker 部署冒烟测试与镜像构建。**须等待对应 GitHub Actions 全部成功并确认 Packages 标签可用后，再执行升级。**

- 镜像：`ghcr.io/anacondakc/yanxing:v0.1.1`
- 平台：`linux/amd64`
- 稳定版镜像发布成功后同步更新 `latest`；生产部署建议固定版本标签。
- 预构建镜像上传上限为 `26214400` 字节，运行时须保持一致；GHCR 包若为私有需先登录。

在 `.env` 中设置 `YANXING_IMAGE=ghcr.io/anacondakc/yanxing:v0.1.1` 后：

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --no-build --wait --wait-timeout 180
docker compose ps -a
```
